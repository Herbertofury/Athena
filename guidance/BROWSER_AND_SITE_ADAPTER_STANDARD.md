Owner requirement, November 28, 2026. Applies to **Noxviola and every owned browser surface**, including Enderloom’s embedded browser and Athena’s Project Constellation provider workspace. Extend the existing [M1 provider lane](../docs/PORTFOLIO-ALIGNMENT.md#m1--provider-and-site-adapters-first-cross-repository-execution-lane), [frontier acquisition standard](WEB_ACQUISITION_FRONTIER.md), and [reuse registry](registry/shared-capabilities.json). Do not start another crawler, catalog, theme system, or private account store.

## Browser requirements

- **Container picker:** New Tab, then named containers with color and icon, then **Add new container** and **Manage containers**. Create, rename, recolor, reorder, choose a default, assign sites, clear/reset individually, and confirm what an individual removal affects. See which container each tab, pane and popup is using. Reopening in another container does not copy credentials. Apply the user’s supplied menu layout without publishing their screenshot or labels.
- **Split view:** split two eligible live tabs, drag or keyboard-adjust the divider, swap, select either pane, navigate independently and unsplit without a needless reload. Restore both original tab/container identities. Panes may use two different accounts on the same origin. Never use an iframe in place of a browser when it breaks sign-in, navigation, accessibility or real isolation; label supported external handoff honestly.
- **Isolation:** engine-level profiles or storage partitions, not cookie switching or cosmetic labels. Verify cookies/auth, local and session storage, IndexedDB, Cache Storage, service workers, permissions, popups, approved OAuth return, downloads, session restore and one-container reset without affecting neighbors. Never include session tokens, passwords or device-bound keys in portable exports. Disclose host/OS restrictions.
- **Constellation acceptance:** the user can sign into ChatGPT account A and B in two visible containers, with a third Claude container in the workspace. Switching or restoring panes keeps the right identity and draft. It does not send, retry or switch accounts on the user’s behalf. Separately authorized actions bind to provider, container and assigned tab. Use supported provider actions; no access-control/rate-limit workaround, token extraction or unrestricted remote control.
- **Chrome, Firefox, Edge and Opera GX packs:** installable, switchable modes with visually familiar chrome, tabs, sidebar, menus, shortcuts and expected workflows. Retain the default and reset/rollback. Maintain a feature-level matrix for tabs/groups and vertical layout, profiles/containers, workspaces and sync/import, downloads, pop-out, PDF/reader/accessibility, per-tab controls, privacy/settings and extension support. A pack can change style without altering security policy or identity. Test behavioral equivalence in each real host; record native/equivalent/partial/blocked with observed version, platform and proof. Do not claim proprietary services, stores, licensed assets or DRM compatibility until verified; preserve existing features and provide supported alternatives/handoff.
- **Extension compatibility is not theming:** independently test Chromium Manifest V3 and Firefox WebExtensions API coverage, permissions, install/update/revoke, signing/store restrictions and per-container scope. Show an unsupported API before installation. Never import arbitrary privileged scripts through a theme or loosen security-origin indicators.

Primary references: [Firefox containers](https://support.mozilla.org/en-US/kb/how-use-firefox-containers), [Firefox split](https://support.mozilla.org/en-US/kb/split-view-firefox), [Chrome split](https://support.google.com/chrome/answer/16971124), [Chrome extension APIs](https://developer.chrome.com/docs/extensions/reference/api), [Edge split](https://explore.microsoft.com/en-gb/edge/features/split-screen), [Edge engine profile candidate](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/multi-profile-support), [Opera GX split](https://www.opera.com/gx/features/splitscreen) and [GX Mods](https://www.opera.com/gx/features/mods). Reference behavior is not a claim of parity.

## Site adapter and scraping requirements

1. Extend Athena’s [existing provider fixture package](../engineering/experiments/provider-release-contract/) and registered candidate paths, not a new release/downloader implementation. Record provider-qualified project and exact release/file identity, author/uploader roles, supported game/runtime/loader, release time, links and evidence. Keep required/optional/incompatible/related separate; unknown is not “none.”
2. Declare every provider operation separately: discover, metadata, exact releases/files, relations, media, follow and permitted download. Prefer official API/feed, then permitted public HTTP/HTML, then authorized isolated browser rendering only when needed. An access wall, bot challenge or paywall yields manual-required, unsupported or partial with a safe fallback. Respect rate limits and retry times. No cookie/token export to the generic scraper, no shared private cache, no unauthorized redistribution.
3. A provider adapter defines semantics, a renderer supplies authorized HTML, and a downloader supplies bytes. Feed normalized public results into Modding-Knowledge. Keep authentication, cache, downloads and portable state owned by the host. Stage supported downloads; validate provider IDs, allowed redirects, expected size/hash, cancellation, restart, last-good state and rollback. Record unknown integrity transparently. Never install a scrape result automatically.
4. Run the same fixtures and permitted live checks in Enderloom and ModHunter before publishing shared compatibility. Reject regressions in full output, source IDs, file variants, filters, dependencies, follow state, preservation or security. Measure full completion, p95/p99, peak memory, requests and transferred bytes. Compare the best existing JS/Python/Go path against Rust candidates without forcing a port.
