# Workbook: evidence before administration

## What to use

Read START-HERE.html in a browser without a server, or read the individual lesson documents under shared/. Each lesson has six teaching paragraphs, three goals, a worked example, a literal local command, six practice steps, three evidence items and three original checks. Answers are available for self-review, not a certification score. The path takes approximately 550 minutes, with additional time for careful reflection.

## Learning sequence

1. Hierarchy: scopes, lifecycle and cross-group dependencies.
2. Access: identity, directory roles, RBAC and data-plane boundaries.
3. Governance: policy findings versus lock decisions.
4. Storage: redundancy requirements versus access and recovery.
5. Network: route ambiguity, layered NSGs and absent DNS evidence.
6. Compute: measured capacity assumptions and a binding ceiling.
7. Monitoring: incomplete windows and exact threshold semantics.
8. Recovery: dependency order versus freshness and restore proof.
9. Cost: exact allocation, unallocated ownership and non-capping budgets.
10. Capstone: findings, missing evidence and a prioritized review plan.

## A repeatable study method

Before running a command, inspect its fixture and write a prediction with a reason. Run the literal Python command from the workshop root. Save the returned JSON without rewriting fields to match your expectation. Explain mismatches using the model's documented rules and limitations. A real observation and a paper alternative are different evidence types; label both clearly.

Without Python, complete the examples on paper and mark all execution unperformed. Reading expected values is not the same as running the exercise. No real Azure actions are needed or authorized by these instructions.

For each lesson retain: a reasoning artifact, the local receipt if executed, and a list of absent real-world checks. Do not include credentials, tenant identifiers, personal data or actual organizational configuration. Fictional labels are sufficient.

## Capstone acceptance

The final review should identify business requirements, connect each claim to a receipt, retain all five modeled risks, and preserve the three missing-evidence categories. A good submission explains what the model cannot establish and prioritizes the next validation without asserting that it happened. It is acceptable and often necessary to conclude that evidence is insufficient.

## Boundary of achievement

Completion demonstrates practice with these explanations and bounded fixtures only. It does not cover every AZ-900 or AZ-104 objective, validate Azure service behavior, award a Microsoft credential or prove practical readiness. Administrative implementation is enrichment beyond selected AZ-900 concepts. Current AZ-104 effective-date verification is incomplete because official material retrieved on 2026-11-08 conflicted; use the coverage map as a partial study aid, not an authoritative current exam checklist.
