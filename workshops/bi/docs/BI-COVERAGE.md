# Coverage and unexecuted product practice

This module contains eight original conceptual lessons, 24 original explained checks and eight fixed Python teaching models. It extends the existing SQL/CSV workshop; it does not replace Power BI practice or complete PL-300 preparation.

The dated partial comparison uses the official [PL-300 study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/pl-300), skills measured as of 20 April 2026 and page updated 30 October 2026. Review the current objectives for your exam date and language. Exam domain weighting is not a measure of this workshop’s coverage.

## Selected thematic links

- Transformations: data preparation concepts, explicit types and reject decisions. Actual connectors, Power Query, M and query folding remain unexecuted.
- Star models, context and dates: selected modeling concepts and hand-checkable examples. Actual relationships, DAX evaluation, context transition, calculation groups, time-intelligence configuration and performance tooling remain unexecuted.
- Report planning: denominators, visible units, alternative text and reading-order requirements. Native visuals, filters, bookmarks, drillthrough, Copilot, mobile layout and assistive-technology behavior remain unexecuted.
- Refresh and access: storage/freshness tradeoffs and the distinction between workspace capabilities and RLS. Gateways, credentials, scheduling, workspace/item permissions, role enforcement, exports, sharing, sensitivity labels and governance remain unexecuted.

See the [workbook](WORKBOOK.md) for the lesson-by-lesson comparison and expected local results. Each source supports a narrow platform fact, not an endorsement of the teaching exercise or proof of mastery.

## Exact local evidence

The reference runtime is Python 3.12.14/Linux. The supplied commands perform in-memory parsing, validation, filtering, arithmetic and declared-plan checks. They never run Power BI, M, DAX or an external query. The role classifier cannot protect data: all synthetic fixtures are readable. The report checklist cannot establish visual or accessibility conformance. The calendar validator is a deliberately fixed full-year 2026 contract, not a universal calendar-feature specification.

A script-free HTML guide and literal code snippets support flexible study. Paper predictions are useful but must not be labeled executed tests. Browser and screen-reader acceptance of the integrated application are separate gates. No publisher endorsement, objective-completion percentage, official score prediction, exam readiness or production assurance is claimed.
