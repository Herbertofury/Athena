# Cloud evidence worksheet and capstone

Study label: __________  Date: __________  Python / OS: __________

For every result choose **prediction**, **executed local model**, **executed local file operation**, or **unexecuted real-cloud lab**. Do not infer cloud experience from local test results. Use synthetic facts only.

## Workload and responsibility

Describe the report service’s users, data, update pattern, normal/peak demand and recovery needs. Compare an IaaS, PaaS and SaaS approach. State deployment model separately. For data access, account removal, OS patches, service configuration and restore verification, record owner, evidence and review trigger. Where would current service-specific documentation be required?

## Access boundary

Split the three fixture paths into segments. Predict narrow and broad scope lists. Explain why dev-tools is not a child of dev. List the omitted principal, action, condition and policy factors needed for a real IAM decision. Record both network-gate results, then describe the next authorized evidence you would collect for each. Do not change real rules or grants.

## Data interface

Choose an interface for report documents, a VM disk and an application requiring shared-file semantics. Explain each assumption. Describe a case where current data is durable but an earlier recovery point is still needed. Which provider-specific behavior remains unknown?

## Capacity and failure

Write demand, per-replica capacity, target percentage and all units. Calculate needed count, clamped count, target capacity and physical capacity. Explain why the baseline can miss target headroom without exceeding the modeled physical limit.

For both failure placements, record replicas before/after, target capacity before/after and whether 500 rpm fits. Draw a shared dependency that would invalidate a simple zone-only conclusion. State why no availability percentage or real failover result follows.

## Recovery evidence

Draw minute 580, 600 and 650. Label the data gap and downtime; compare separately with 15-minute RPO and 60-minute RTO. Run the local restore if available and record all verification flags. Which checks are byte-level only? Which application, key, access, dependency and regional recovery checks remain unexecuted?

## Cost assumptions

Calculate always-on and scheduled compute, storage and transfer in fictional credits. State what changes and stays fixed. Identify at least five omitted real-billing considerations. Explain why an alert is not an immediate hard cap. No provider pricing or account offer was checked for an actual purchase or deployment.

## Change review

Predict each add, remove and modify in ID order. Explain the reports-removal and web-exposure risks. Who would need to decide a real intended audience, retention requirement and deployment authorization? What independent evidence would a rollback or restore require? Record `applied: false` honestly.

## Capstone: approve the learning evidence, not a deployment

Prepare a one-page fictional service review:

1. Purpose, users, data and service-model choice with one unresolved requirement.
2. Responsibility owners and a narrow access intention.
3. Network/storage assumptions and what would verify them.
4. Capacity/failure calculation, including a limit the model omits.
5. Recovery objectives, timeline result and actual local-restore evidence if executed.
6. Cost components, invented rates and missing-cost items.
7. Change risks, no-apply status and a future validation/cleanup checklist.
8. Explicit status: **real-cloud provisioning, IAM, networking, load testing, failover, backup recovery and billing verification are unexecuted**.

Choose one safe variation in a private fixture copy. Record the original prediction, actual model output and explanation. Add a test for your changed assumption without deleting baseline tests. No real-cloud action is part of this capstone.

## Reflection

Can you explain a counterexample, identify a hidden dependency, distinguish a target from a measurement, and state what your evidence does not establish? Those are useful foundation skills. A local pass is not provider certification, complete exam readiness or production approval.
