# Answer key: claims justified by observed evidence

Do not memorize commit IDs. Check relationships and contents. The synthetic identity, fixed timestamps and fixed inputs make repeated runs deterministic on the tested Git installation; the hash's particular spelling is not the lesson.

1. **Snapshots:** `before != after`. Old text is `Decision: baseline\n`; new text is `Decision: reviewed\n`. Both remain readable by full revision. `clean=true` only means no tracked or untracked changes were reported.
2. **Staging:** `status_before` is `MM notes.txt`: index differs from HEAD and working tree differs from index. The cached diff adds `Decision: staged`; the other diff adds `Decision: unstaged follow-up`. The commit contains the staged text; the working file contains the follow-up. `clean=false` is expected, not a failed lesson.
3. **Branches:** `parents` is exactly `[main_before_merge, feature]`. Both tips diverged from the baseline; merging produced a new commit. `conflict_observed=false`, `unmerged_after=""`, `clean=true`. The feature note survives in resolved_content and main's version 2 survives in release_content. Git's successful text merge is not a semantic test.
4. **Conflict:** the same line differs on both sides. The recorded markers contain `<<<<<<< HEAD`, `=======`, and `>>>>>>> feature`. The merge returns 1 and creates unmerged index entries; the program verifies these before treating it as an expected conflict. The fixed explicit resolution is `Decision: feature and main reviewed together\n`. unmerged_before records the unresolved index stages; unmerged_after is empty. The completed merge has two parents, no unmerged entries, and a clean worktree.
5. **Recovery:** history is `[revert, bad, baseline]`. The bad commit remains reachable; a new commit reverses its change. `release.json` is restored to `{"feature": false, "version": 1}\n`. baseline_content and restored_content are observed equal, so baseline_restored=true. The lab does not rewrite a shared history, reset files, or contact a server.
6. **Revision tests:** a clean exact baseline passes three fixed data checks. A working change returns `dirty-worktree`; a clean different HEAD returns `revision-mismatch`. Committing the note change allows a new, separately bound pass. Committing version -1 returns `assertion-failed`, with `version_positive_integer=false`. These are real Python predicate checks against data obtained from `git show` for the full revision. They are not application tests or an arbitrary-code runner.
7. **Provenance:** the sorted manifest contains README.txt, notes.txt, release.json. Each digest covers that committed file's exact UTF-8 bytes. USTAR entries have fixed order, names, timestamps, mode, ownership, and no compression metadata; two builds are byte-identical. Flipping one content byte changes the archive SHA-256. The attacker who can replace both payload and reference hash can replace both consistently: a digest alone supplies no trusted identity, signature, or source-of-truth guarantee. `authenticated=false` remains correct.
8. **Capstone:** the merged HEAD is the exact tested revision and the archive's revision. The local gate checks fixed content and matching revision evidence. It does not publish, deploy, sign, authenticate authors, validate CI, scan dependencies, or prove production safety. A good review note distinguishes this narrow passing evidence from those remaining responsibilities.

Expected negative outcomes are useful evidence. An unexpected Git error or missing prerequisite must instead produce a nonzero runner exit and no success envelope.
