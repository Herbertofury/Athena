## Guided capstone

### Design a resilient web workload

1. Design a fictional web application with compute, relational data, object storage and a delivery path.
2. Specify identity policies, public/private network boundaries and encryption/key responsibilities.
3. Model one-zone failure, data corruption and a restore; state RTO/RPO and dependency order.
4. Compare two architecture options for performance, resilience, operations and cost.
5. If later deploying, obtain a budget decision and use disposable resources with explicit teardown evidence.

### Acceptance evidence

- Architecture and request/data-flow diagrams.
- Trade-off table and recovery test plan.
- No deployed/available claim without a real measured deployment.
