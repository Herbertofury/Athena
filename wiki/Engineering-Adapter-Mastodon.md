# Mastodon REST adapter: offline projection and bounded public replay

[Adapter laboratory](https://github.com/Herbertofury/Athena/wiki/Engineering-Site-Adapters) · [Social platform research](https://github.com/Herbertofury/Athena/wiki/Engineering-Social-and-Publishing-Adapters)

Reviewed **2026-11-02 UTC**. The [normalizer](https://github.com/Herbertofury/Athena/blob/main/engineering/experiments/site-extraction-lab/mastodon.py) implements an offline Mastodon REST projection with defensive [synthetic tests](https://github.com/Herbertofury/Athena/blob/main/engineering/tests/test_site_extraction_mastodon.py). The [public replay receipt](https://github.com/Herbertofury/Athena/blob/main/engineering/experiments/site-extraction-lab/mastodon-validation-2026-11-02.json) records two actual public organization profiles, three captured timeline pages and 15 outer statuses. One boost and one video attachment were observed. This establishes sample-scoped parsing and returned-link pagination, without establishing playback, complete history, authenticated access or full adapter acceptance.

## Identity, authorship and content

Retain `(apiOrigin, id)` for both statuses and accounts, separately from the federation `uri` and presentation `url`. API IDs remain opaque strings; number coercion loses precision and bare IDs collide across instances. Account `uri` is documented from Mastodon 4.2.0, so older responses retain an absent field state rather than inventing an actor URI from a handle. `acct` is an alias, not the identity key. The official docs permit nullable profile URLs. Avatar and static-avatar fields are sourced only from the account object. A preview image cannot become a person's avatar. [Account](https://docs.joinmastodon.org/entities/Account/) (RDSOC02002).

The caller supplies the HTTPS API origin established by its capture/transport. Optional expected status/account IDs and status federation URI detect response mismatches. A remote author's federation origin can differ from the API server; this normalizer does not reject that valid federation case or claim to verify remote ownership through network resolution. It supports HTTP(S) federation references, not arbitrary ActivityPub identifier schemes. Canonical identity joins across instances require a separately verified federation URI; absent URI does not justify merging handles.

Keep the exact original HTML in memory. Renderers still need their own HTML and URL sanitization. Preserve creation/edit timestamps with timezone offsets, visibility, sensitive flag, spoiler text, mentions, tags, emoji, poll and reply evidence. `fieldStates` distinguishes absent, null and value; `rawStatus`/`rawAccount` retain source JSON in memory. The adapter does not manufacture plain text from clipped web UI content. [Status](https://docs.joinmastodon.org/entities/Status/), [formatting guidelines](https://docs.joinmastodon.org/api/guidelines/) (RDSOC02001, RDSOC02004).

A boost remains the outer event authored by `boost_actor`; its `reblog` retains the original status author, identity, body and attachments separately. Quote data and link cards occupy separate scopes. Card HTML/images and quoted attachments never become the current author's body or media. Attachment order is preserved; image, video, gifv and audio remain distinct. Descriptions, metadata, full delivery URL, remote URL and preview URL stay in memory. Video/gifv previews have `video_poster` roles; their existence does not prove playback. A null processing URL or unknown type yields incomplete media. [MediaAttachment](https://docs.joinmastodon.org/entities/MediaAttachment/) (RDSOC02003).

Quote handling is version-specific: the Status documentation dates `quote` to 4.4.0; quote state additions followed in 4.5.0. Only `accepted` quotes are projected as nested statuses. Pending/rejected/revoked/deleted/unauthorized/blocked/muted and unknown states do not expose their supplied nested bodies. Accepted shallow/missing status becomes `accepted_unavailable`. The documented 4.5.7 deletion-response exception can include a quoted status regardless of state; presence alone therefore cannot authorize display. **No quote was observed in the actual captures.** Quote support is documented and synthetic-tested, not live-validated or promised across all compatible servers. [Quote](https://docs.joinmastodon.org/entities/Quote/) (RDSOC02005).

When an accepted quote supplies both `quoted_status_id` and an embedded status, their opaque API IDs must agree; contradictory or incorrectly typed IDs fail normalization. Unknown attachment type strings remain intact in runtime records but become the constant `unknown` in public receipts, preventing arbitrary type-field text from escaping the publication whitelist. These cases are synthetic regressions; the dated public replay retains its original implementation hashes.

## Pagination and publication boundary

`normalize_timeline_page` takes the captured response array, API origin, exact request URL, optional HTTP Link value and optional expected account ID. It follows no links itself. Returned next/prev references are retained in memory only after enforcing the same HTTPS origin and exact API resource path. Credentials, fragments, self-loops, repeated next/prev relations and anchor-context changes are rejected. The header tokenizer preserves commas inside URI references and quoted parameters; it is a deliberately constrained parser, not a general RFC 8288 implementation. The caller must retain a visited-page set and enforce page/time/byte limits across requests. An absent next link is only a terminal-page hint for the captured window; `completeImport` is always false. [API pagination guidelines](https://docs.joinmastodon.org/api/guidelines/), [account statuses](https://docs.joinmastodon.org/methods/accounts/#statuses) (RDSOC02004, RDSOC02006).

Only `receipt()` is intended for public evidence. It publishes whitelisted hashes, byte counts, typed media presence and pagination flags. No raw body, bio, alt text, preview prose/HTML, display names, arbitrary URL paths, tokens or cursors are projected. Private/direct, unlisted, absent and unknown visibility produce a constant redacted status with **no identity, text hashes, counts or nested data**. This deliberately stricter publication policy does not change the in-memory visibility value. Nested private statuses are redacted independently. Runtime objects are private working data and must never be dumped as evidence.

## Actual observations and remaining gates

The official Mastodon organization account on mastodon.social supplied a profile and five public timeline statuses, including one boost. Godot's [official community page](https://godotengine.org/community/) identifies its [Mastodon account](https://mastodon.gamedev.place/@godotengine); that public account supplied a profile and two pages of five statuses, including one video. The second Godot request used the first page's returned same-origin `next` link. No duplicate outer status IDs occurred across those two pages. Raw JSON and HTTP headers stay outside the repository; the committed receipt includes capture hashes and minimized normalized output. The public [Mastodon API guide](https://docs.joinmastodon.org/client/public/) documents unauthenticated public-data exploration; individual servers can disable access (RDSOC02007–RDSOC02009).

No credentials, private accounts, server joins, follows or relationship mutations were used. No media bytes were downloaded. The actual captures do not cover quotes, image/gifv/audio attachment variants, avatar migration, blocked users, custom servers, processing failures or deletions. Those mapped paths require further actual authorized captures before broad acceptance. Public visibility is not a blanket license for redistribution.

Run from the repository root:

```sh
python3 -m unittest discover -s tests -p test_site_extraction_mastodon.py -v
python3 experiments/site-extraction-lab/mastodon.py /private/capture.json --origin https://instance.example --kind status
```

For a timeline CLI replay, use `--kind timeline --request-url URL` and optionally `--link-header-file FILE`, whose file contains only the captured Link header value. CLI output always uses the publication receipt. Network collection, visited-page tracking, MIME/decode/playback checks and native follow operations remain separate future work. Reusing only page-body HTML extraction was rejected because it loses stable API identity, explicit boost/quote roles and pagination evidence; REST projection still depends on server availability and version differences.
