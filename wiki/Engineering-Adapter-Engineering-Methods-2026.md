# Full-fidelity retrieval methods, snapshot 2026-11-02

Official sources inspected 2026-11-03 UTC. Release dates are separate from checked dates. Living documentation is observed on the checked date, not proof it existed before the snapshot cutoff. This pass establishes documented candidates and executable experiment proposals, not speed measurements or target acceptance.

## Existing Atlas scope and missing work

The inspected repository already contains the round-four 476 service/scope catalog and Discourse/Mastodon normalizers. Adding those communities again would inflate counts. Before this pass, the research catalog contained Playwright but none of the eight extraction-tool entries added here. Existing upstream-candidates documentation already lists yt-dlp, gallery-dl, Crawlee and Scrapy; the value here is catalog integration, release validation and equivalent-output tests.

Inspected Atlas Rust code has durable jobs, fenced leases, provider cooldowns, bounded JSON reading and a current upstream request reservation mechanism. A focused search across apps/atlas-lab/src found no ETag, If-None-Match, If-Modified-Since, Last-Modified or Vary revalidation implementation. public_http.rs handles MIME and body bounds, while upstream_reviews.rs reads numeric Retry-After and rate reset. An isolated HTTP policy experiment therefore addresses a concrete gap; it must preserve these existing protections.

## Ranked engineering decisions

1. **Prioritize representation-safe incremental retrieval.** Add an offline policy model before adding network clients: request identity, validators, 304 reuse, Retry-After and response-state classification. Fewer bytes are useful only after identical content, warnings and freshness states are proved. HTTP revalidation does not prove a substantial end-to-end improvement by itself. [RET26016] [RET26021] [RET26022]
2. **Separate acquisition from normalization and presentation.** Prefer authorized structured APIs/feeds where they preserve required fields, then scoped embedded JSON/DOM. Browser execution is a capability escalation for lazy/windowed content, not a universal first step. Retain per-field source locators and explicit missing/unknown states. Playwright network observation can identify the payload actually loaded during authorized UI use, but endpoint discovery does not establish a supported public API. [RET26007] [RET26008] [RET26017] [RET26019]
3. **Compare Crawlee and Scrapy as orchestration alternatives.** Crawlee stable 3.18.2 (September 29) fixes a hung page.close and timed-out context leak. Its v4 /next changes remain a separate prerelease evaluation. Scrapy offers durable clean-resume jobs and per-slot latency throttling. Neither substitutes for exact record/media normalization or transactional cursor advancement. [RET26001] [RET26009] [RET26010]
4. **Evaluate Crawl4AI for DOM replacement, not text summarization.** Its virtual-scroll guide distinguishes a fixed-sized DOM window from append-only infinite scroll. A final-page snapshot loses earlier items in the former. Pin 0.9.5 and compare captured stable IDs and typed media with an independently enumerated oracle; do not accept an LLM-produced author/date/body as source truth. [RET26002] [RET26003]
5. **Use Browsertrix as scoped media QA.** Stable 1.15.2 was released October 29; the release fixes shared sitemap reading. Earlier 1.15.0 includes expanded auto-QA. Behaviors load lazy images, autoplay media and scroll site-specific views. Full archives are unsuitable for the default minimal-retention pipeline; use an explicitly scoped public replay fixture or private ephemeral QA capture. The documented YouTube behavior currently selects 360p mp4, a material limitation for a full-resolution fidelity requirement. [RET26004] [RET26005] [RET26006]
6. **Keep specialist extractors as sidecars with typed contracts.** yt-dlp metadata mode and gallery-dl can reduce bespoke media handling on permitted routes. Normalize ordered variants, thumbnails/posters, actual media kind, durations and canonical source identity; run authorized playback separately. Active gallery-dl development moved to Codeberg April 5, 2026; GitHub is infrastructure, not the current source-of-truth repository. Keep Atlas's existing yt-dlp 2026.10.26 compatibility/security review. [RET26013] [RET26014] [RET26015]
7. **Treat generic text/parser tools as bounded layers.** Trafilatura can extract article text/metadata but comments default on while images and links are opt-in. It must not overwrite a complete creator/post/media graph with article-like output. selectolax is a parser comparison candidate; its current Lexbor documentation warns even read-only CSS calls on a shared parser are not thread safe. Use one parser per worker and compare complete normalized results. [RET26011] [RET26012]

## Offline HTTP revalidation policy experiment

Decision: Can conditional refresh preserve exact output/access/freshness behavior while reducing transferred bytes and unnecessary extraction?

Control: unconditional GET with existing body limits, MIME/status validation and last-good retention. Candidate: a pure policy engine plus mock transport. No real credentials, content or network required. All fixtures labeled synthetic.

Representation identity must include method, effective request URL/query semantics, accepted representation, selected Vary request fields and a separate opaque account/access partition. URL normalization must not reorder/drop query components without provider proof. Locale and API version belong in the key when relevant. Never persist raw Authorization/Cookie values as cache keys or provenance. Vary:* prohibits reuse by this bounded cache. Public and authorized/private records must not share storage partitions. Vary is a server-declared dimension, not a complete substitute for application's explicit account partition. [RET26021]

Validators: use returned ETag as an opaque string including weak prefix and quotes. With an ETag, send If-None-Match; only use Last-Modified/If-Modified-Since as the fallback policy. RFC9110 gives If-None-Match precedence when both are sent. A body hash is an application integrity check and cannot be invented as a server ETag. [RET26016]

304 handling: require a matching previously validated stored representation, its correct partition, an intact content hash and the original request's applicable validator. Treat a 304 without reusable local content as refetch-required/error, not an empty successful document. Preserve normalized payload/content version; update validation metadata according to RFC9111. Account access revocation and login-wall responses are not "unchanged." A cached HTTP result and current source publication/edit time remain distinct. [RET26016] [RET26021]

Status handling: separate fresh-success, validated-unchanged, stale-last-good, login-required, forbidden, rate-limited, schema-invalid and partial. A 401/403/429/5xx cannot erase last-good records or advance the history checkpoint. Do not serve stale data as fresh; freshness rules and application retention policy are separate. 429 is not cacheable as a successful source representation. [RET26021] [RET26022]

Retry-After: parse both nonnegative seconds and HTTP-date. Inject wall time and monotonic scheduling into the policy test. Cover dates in the past, overflow, malformed headers, clock skew and cancellation; bound delays by explicit local policy while preserving an upstream not-before constraint. Do not reset a valid cooldown because an error arrived quickly. Persist provider cooldown before requeueing and avoid retry storms across workers. [RET26016] [RET26010] [RET26022]

Required negative cases: same URL/different account; same URL/different Accept or Vary; Vary:*; strong/weak ETags; changed weak ETag; 304 without seed; tampered seed; unchanged bytes but changed headers; no-store; private; login redirect; missing/incorrect MIME; 200 truncated body; 429 with both Retry-After forms; 503; malformed ETag; edit changes media ordering; cancellation during normalization; cancellation after record commit but before checkpoint commit. Pass all output/access gates before any performance comparison.

## Cursor, worker and media parity experiment

Decision: Which acquisition/orchestration path completes identical creator history with correct edits and media under bounded resources?

Use the current parser/runner as control. Compare API/HTTP-first, browser DOM, observed browser response, Crawlee and Scrapy as separate cohorts; do not change both parser and concurrency while attributing the result to one tool. API-specific schemas remain separate adapters. A Lemmy 1.0/v4 migration guide documents cursors and renamed endpoints; this is a version negotiation test lead, not evidence every deployed instance supports v4. [RET26018]

Commit normalized records and the next cursor together; do not advance checkpoints for rejected/truncated pages. Repeated cursors, overlap, duplicate IDs, pinned items, deleted items, edited old items and retries must preserve progress and partial-history truth. Distinguish a terminal page hint from a full import from the requested boundary. WordPress modified_after is a useful edit-aware refresh primitive when supported; site-local date and date_gmt must retain their timezone meanings. [RET26019]

For browser windowing, enumerate item IDs during each scroll before nodes disappear. Retain media association with each post while updating the dedupe map; do not collect all page images into the last visible post. Repeated scrolls require a declared stop condition, bounded resources and a continuation; a scroll timeout is incomplete history. [RET26003]

Required exact-output oracle: original author ID/profile/avatar separately from reblogger/uploader/session identity; full body tree with links/formatting; source publication and edit times with precision; canonical item IDs; ordered image/GIF/video/audio blocks and variants; poster/preview versus original; quoted/reblogged source; access state; account-native relationship state separately from local watch state; warnings and history completeness. Metadata present, decoded image, moving animation and successful video playback are separate evidence levels.

Use representative small/typical/large publishable fixture sets plus malformed/partial pages. Hold rate/concurrency/CPU/RSS budgets fixed. Run at least five independent samples per configuration, cold and warm separately. Include process startup, download, parsing, full normalization, integrity checks, transactional commit, UI-visible completion, cancellation and resume. Record p50/p95/p99 completion, peak RSS, CPU, provider requests, transferred bytes, full output hashes, media mismatch count and integration effort. Reject any apparent win that drops posts/media/warnings, changes access boundaries or skips validation. These are planned comparisons; no benchmark was executed.
