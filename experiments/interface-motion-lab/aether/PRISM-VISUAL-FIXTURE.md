# Prism interaction parity fixture (behavioral; no Prism code or art)

Reference: [Obsidian Prism revision d47c5d9](https://github.com/RMvdesi/obsidian-prism/tree/d47c5d9ccb8886025d0f8b1bdf99bc1b5e4b1d07), **GPL-3.0-only**. This is an original test procedure. Capture separately in an upstream reference workspace; do not redistribute upstream assets with the test. Record the app version, named palette/motion/profile values, window bounds, scale, GPU mode, and the recording's timing. Do not use the upstream installer, host injection or daemon as part of the shared component.

| Scenario | Deterministic input | Observable acceptance |
|---|---|---|
| Home hover | 1280×800 DPR 1 and 1920×1080 DPR 2. Enter a blank left margin at (15%,35%); 10 equal steps toward (30%,35%) over 800 ms; hold 2 s. | Local light/aura follows position. Slow movement creates no chain of discrete skimmer waves; no interaction takes focus. |
| Skimmer | Move the same distance over 150 ms, then turn a corner at the final point. | Repeated traveling wavelets appear along the fast path as distance thresholds are crossed, not one ring per native hardware packet. They decay away. |
| Primary press | Primary press at normalized (20%,40%); take t+0/100/250/600/1200 ms crops; repeat with secondary button. | Main press is an expanding, damped glyph-wave disturbance at the press origin. Secondary button does not make this wave. Compare wave radius/alpha curve and phase, not screenshots with app chrome. |
| Leave / idle | From same cursor trace, move outside the surface; wait 1.5 s, then reenter and press. Hide and reshow independently. | Aura clears, animation stops when settled; reentering/pressing wakes the surface without a flicker. Hidden/blurred state suspends rather than queuing lost work. |
| Conversation | Compare home and enabled conversation modes. Move/click over a blank margin, then over typing area, text, link, buttons and scroll. | Conversation modes apply their own intensity thresholds; protected controls keep normal behavior with no decorative press on them. |
| Motion / fallback | OS reduced motion, fallback Canvas2D, simulated context-lost, profiles Balanced and Performance, static wallpaper separately. | Reduced motion suppresses reactions; fallback stays visually composed without a white box. Static or video wallpaper is separate and never a proxy for shader parity. Record renderer transitions and restoration. |
| Mobile extension | 390×844, tap blank margin, swipe vertically, cancel the touch. | Press response where applicable, no sticking, no interception of scroll or native controls. This is a portable host extension, not established native Prism phone parity. |

Files guiding what to compare (reference only): [home interaction controller](https://github.com/RMvdesi/obsidian-prism/blob/d47c5d9ccb8886025d0f8b1bdf99bc1b5e4b1d07/home-ripple-host.js), [field and glow](https://github.com/RMvdesi/obsidian-prism/blob/d47c5d9ccb8886025d0f8b1bdf99bc1b5e4b1d07/ripple-core.js), [worker and fallback](https://github.com/RMvdesi/obsidian-prism/blob/d47c5d9ccb8886025d0f8b1bdf99bc1b5e4b1d07/src/runtime/ripple-worker.js). The [vial](https://github.com/RMvdesi/obsidian-prism/blob/d47c5d9ccb8886025d0f8b1bdf99bc1b5e4b1d07/vial-core.js) is a separate component: if requested, add fill step/spring response, meniscus poke, damped convergence and true zero-FPS settle to its own fixture. An independent shared implementation should not copy Prism's shaders, textures or implementation unless the receiving licensing lane is verified compatible.
