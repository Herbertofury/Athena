# Accessible reports and secure distribution

Communicate accurately and control who can see what.

## Learn

Choose visuals from the question: comparisons, trends, distributions and relationships need different encodings. Label units and time windows, avoid misleading axes, and make color meaning accessible.

Row-level security filters data for roles; it must be tested with actual role behavior and sharing arrangements. Workspace roles, app audiences and dataset permissions affect access independently.

Publishing requires a refresh plan, data-source access, ownership and monitoring. A report that works only on the author’s laptop is not an operational service.

## Worked example

A sales manager should see only their region. Test the security role and the actual sharing route; hiding a page is not a security boundary.

## Practice safely

1. Design a one-page report for a fictional manager.
2. Include keyboard/readability and color checks.
3. Define a row-level access rule and test cases.
4. Write refresh failure and ownership procedures.

## Check your understanding

Which is not a reliable data security control?

- Tested row-level security
- Appropriate dataset permissions
- Least-privileged source access
- Simply hiding a report page

<details><summary>Answer and explanation</summary>

Simply hiding a report page. Hidden UI can still leave underlying data accessible.

</details>
