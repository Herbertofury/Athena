# Creative AI: web, graphic design and photo/image candidate review

Reviewed 2026-11-13. Evidence level: primary-source documentation review only. No installations, inference runs, quality comparisons, or performance measurements were performed. These are evaluation candidates, not proven replacements for Athena or other projects. “Apache/MIT weights” describes the published artifact license, not a claim that training data and full reproduction materials satisfy an open-source AI definition. Pin model revision, application commit, license text and dependency inventory before deployment.

## Important exclusions and watchlist

- **Qwen-Image-2.1 is not the same license as Qwen-Image.** Inspected LICENSE at commit shown as `f52e6a5` states Qwen Research License, release date September 20 2026, non-commercial research/evaluation only and separate license for commercial use. Keep restricted/source-available, not the permissive production shortlist. [Actual license](https://huggingface.co/Qwen/Qwen-Image-2.1/blob/main/LICENSE).
- **FLUX.1-dev:** model card specifies `flux-1-dev-non-commercial-license`; do not label it Apache because schnell is Apache. [Official card](https://huggingface.co/black-forest-labs/FLUX.1-dev).
- **IOPaint:** Apache-2.0 application but repository is publicly archived. Useful reference/isolated legacy evaluation, not a maintenance-default pick. [Repository](https://github.com/Sanster/IOPaint).
- **Fooocus:** GPL-3.0; upstream states SDXL-based limited long-term support with bug fixes only. Not abandoned by inference, but not the active broad-model roadmap default. [README](https://github.com/lllyasviel/Fooocus/blob/main/readme.md), [license](https://github.com/lllyasviel/Fooocus/blob/main/LICENSE).
- **BiRefNet:** promising segmentation candidate, but keep license verification pending for the chosen weight revision. An upstream issue explicitly requests clarification of weight MIT coverage; issue claims are not maintainer authorization. [Question](https://github.com/ZhengPeng7/BiRefNet/issues/316), [source](https://github.com/ZhengPeng7/BiRefNet).

## Athena implementation contract

Store independent fields: tool code license; weight artifact/license/revision; encoders/adapters/licenses; local versus remote execution; API spend; credential requirement; upstream release/commit; last source check; source claim versus measured result; maintenance state; output provenance. Do not collapse all of these into a green “open source” badge.

Prioritize a local, licensed candidate chain: Krita/Invoke user workflow → ComfyUI/Diffusers executor → explicit permissive model revision → SAM2/rembg masking → Upscayl enlargement. This is an evaluation architecture, not a claim of interoperability already tested. Prefer existing adapters before new wrappers.

Bounded comparison: fixed user-owned/public-license fixtures covering portrait hair, transparent objects, product cutouts, multilingual poster text, UI screenshot, illustration and low-resolution game asset. Run baseline plus two candidates, fixed seeds/settings, equal resource budget. Retain inputs, prompts, hashes, model/code versions, raw outputs, errors, cold/warm latency, peak RAM/VRAM, disk usage, restart/reopen persistence and export roundtrip. For web code evaluate keyboard access, contrast, DOM semantics, mobile layout, console errors, build/test success, dependency security and visual match. For images score alpha halos, OCR fidelity, requested edit compliance, protected-region preservation, artifact rate and human preference blinded to model. No cross-project recommendation until measured target improvement with requirements intact.
