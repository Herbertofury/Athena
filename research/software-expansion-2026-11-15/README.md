# Athena software discovery: second expansion

## Goal beyond the goal

Help a person choose a well-supported tool for a concrete computer task, including specialist work they did not know their PC could support.

## Ambition and execution plan

**Altitude:** grow from isolated entries to useful comparison sets, then keep those decisions reviewable through shared canonical data, evidence refresh and verified publication. The three rungs are (1) preserve and enrich the published 736 applications; (2) fill thin categories and connect task-specific alternatives; (3) publish the same verified records in the live application and actual Wiki with repeatable audits.

**Depth:** a professional curator would begin with the 112 single-application categories and unresolved evidence, inspect raw official documentation, installation instructions, licenses and dated releases, and compare actual task constraints. The hard target is roughly 300 worthwhile additions and at least 50 decision guides, while strengthening existing comparison sets. Accuracy determines inclusion; these targets are not quotas or ceilings. A bounded, reproducible fixed-string search experiment will compare installed command-line implementations only after equivalent output is established. Its pinned versions and environment limit its conclusions.

**Range:** the verbs are discover, choose, install, compare and maintain. Three independent research streams apply domain-specific methods: communication/RF/industrial systems; bioinformatics/BIM/audio/scientific workflows; and project/business/development/AI/gaming workflows. Integration applies data contracts, identity deduplication, preservation hashes, task-query regression checks, independent source review, HTTP observations and real-browser acceptance.

**Outside judges:** schema and claim-source validation; exact preservation of all baseline application identities and original research snapshots; reproducible query results; complete equivalent outputs before any timing comparison; strict HTTP auditing; full application/native checks; actual Chromium on GitHub Actions; served-catalog SHA-256 equality; and byte comparisons against the pulled live Wiki. A failed hard target or inconclusive observation remains visible.

## Access

- Available: current repository and published catalog, existing research receipts, official web sources, command-line tools, GitHub connector publication, hosted Chromium/native verification, Pages and Wiki workflows.
- Local Chromium is blocked by the host environment. The established hosted acceptance path provides actual-browser execution without bypassing that restriction.
- No downloaded application execution, purchases, invented benchmarks or unsupported universal-best labels are needed for the research batches.
