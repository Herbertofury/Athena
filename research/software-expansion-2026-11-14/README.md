# Athena software discovery expansion

## Goal and execution standard

Help someone choose the right software for a real PC task, including useful capabilities they did not know existed. The expansion must modify and publish Athena's actual catalog, application and live Wiki while preserving prior research.

The ambition ladder is: preserve and enrich the existing records; turn sourced discoveries into usable task-based comparisons; keep that catalog reviewable through reproducible generation, provenance, periodic link auditing and explicit coverage gaps.

The depth pass starts with raw official documentation, repositories, licenses, installation instructions and release evidence. The instruments are a typed record contract, canonical-identity deduplication, immutable baseline hashes, a reproducible database/Wiki builder, query tests, real Chromium interaction tests and recorded HTTP observations. The hard target is hundreds of distinct useful additions without duplicate identities or invented benchmarks. Automated checks and live publication verification determine success.

The research teams cover systems/storage/security/networking, creative/productivity/science/accessibility, and development/automation/AI/gaming. Integration owns the data contract, preserved records, search and comparisons, source-audit workflow, generated Wiki, test gates and publication. Code/research access is available; local Chromium execution is blocked by the host, so actual browser acceptance runs on GitHub Actions.

## Execution brief

```text
Expand Athena into a sourced decision system for PC software. Start from the
existing application and research records, preserve their identities and bytes,
then investigate underrepresented tasks in parallel using official sources.
Add hundreds of distinct worthwhile applications only when source review supports
their identity and documented capabilities. Record licensing, pricing model,
platforms, official installation pages, strengths, limitations, maintenance
basis, alternatives and source claims honestly. Integrate all records into the
main search, taxonomy, task guides and comparison experience. Publish code and
the actual live Wiki. Pass preservation, deduplication, schema, generated-output,
search/filter, real-browser and publication checks; retain failures and unknowns.
Report exact before/after counts and remaining evidence gaps. Never equate
metadata, popularity or HTTP reachability with a verified quality ranking.
```

## Reproducible evidence

- `baseline.json` records source commit, checksums and original counts.
- `*-sources.json` contain research source observations from each team.
- `local-validation.json` records the generated-data, preservation, application-test and public-package checks, with file hashes.
- `search-qa.json` records 37 reproducible task and alternative queries, their exact results and remaining capability-evidence gaps.
- `coverage.json` is generated from the actual integrated database.
- `refresh-queue.json` records unresolved metadata and review priorities without relabeling products as abandoned.
- `data/software/coverage-priorities.json` and the generated Wiki coverage page identify underrepresented task domains and single-candidate categories.
- `local-browser-attempt.json` records the host restriction before any UI checks ran.
- `link-audit.json` distinguishes successful requests, missing endpoints, access blocks and inconclusive checks; its catalog hash identifies the exact data audited.
- `ci-verification.json` retains successful integrated-candidate workflow references and the actual 736-record Chromium report. GitHub Actions artifacts retain screenshots; the pull request records final publication evidence.

Original classifications remain visible, and 77 preserved records still need more field-specific source annotations. The refresh queue contains 355 records; its unknown pricing, licensing, maintenance and source-mapping counts overlap. These are evidence priorities, not application-quality scores.

The original 66 cleanup records, three unranked candidates and one excluded candidate remain in their original snapshot and are searchable in the software workspace under their original classifications. They are not counted as new discoveries. The 105 Windows PC records are imported with every original field retained; dated enrichment overlays update selected current metadata separately. Existing engineering entries and creative-AI/model research are preserved and linked without relabelling them as new applications.
