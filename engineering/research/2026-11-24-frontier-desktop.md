## Techniques worth advancing

- Treat the UI as a dataflow graph: stable IDs, keyed row updates, visible-window rendering, incremental layout, cancellation and background preparation of immutable snapshots. Never optimize by losing offscreen records or hiding an expensive first-use operation.
- Separate text shaping/layout, rasterization, GPU upload, event-to-paint and full first-useful-result. Track cold, warm and sustained interaction, GPU/CPU memory and power where possible; high-refresh displays reveal tail stalls that averages hide.
- Isolate expensive file decode/index operations from the UI thread with bounded queues, cooperative cancellation, backpressure and useful progress. Benchmark the complete user workflow, including result delivery and UI update.
- In native graphics, compare resource ownership, staging reuse, pipeline compilation, synchronization and frame pacing with equivalent geometry, shaders, lighting and resolution. Test the actual game/client/driver where required. Do not promise Vulkan fixes from synthetic samples.
- For browser work, measure standards/extension/media parity and authorized page behavior before selecting an engine. Keep supported isolated rendering as a test route without interrupting the user's desktop.
- Maintain one reusable UI/data contract per compatible target, but allow specialized native and browser implementations when supported evidence justifies them. Current technologies are contenders rather than measured winners.
