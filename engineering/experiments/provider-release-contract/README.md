# Shared provider release contract v1

First implementation slice of [M1 / Athena #363](https://github.com/Herbertofury/Athena/issues/363). This is a dependency-free TypeScript reference and synthetic fixture suite, not a complete provider adapter or declaration of cross-project parity. Run `node --experimental-strip-types --test github-release.test.mjs` from this directory (Node 22+). The exact reference and test blobs were exercised locally on Node 22.16.0, three test groups passed. Consumers pin the reviewed source blob and retain local independent operation; changes flow back here before re-vendoring. No online runtime dependency.

Borrow the strongest ideas from [Modhunter's release parser](https://github.com/Herbertofury/Modhunter/blob/f5bf5e616baf04600d92a532509b3475d2d5e1ba/native/crates/modhunter-core/src/source_adapters/parsers.rs): bind repository, stable release ID/tag, asset ID, exact URL and provider digest/size. Accept a missing digest as unknown, never as a verified provider hash. Reject ambiguous/foreign/incomplete assets instead of silently reporting success. Distinguish HTTP failures from no release; only the caller can establish whether archive fallback is appropriate. This reference parses assets present in the response; it does not establish complete paginated history or file availability. Preserve all permitted asset types (not just mod archives), and validate the actual transfer before promotion. Keep host-specific schemas/operations.

Current official [GitHub releases](https://docs.github.com/en/rest/releases/releases) and [release assets](https://docs.github.com/en/rest/releases/assets) docs reviewed November 24, 2026; API example version 2026-03-10. No live provider requests, performance or end-to-end acceptance claimed by fixture tests. The Rust/Go implementations may consume the same behavioral contract without replacing native code. Open issue tracks actual multi-host acceptance.

## Verified streaming transfer

One backpressure-aware pipeline stages files on the destination filesystem, verifies provider size/digest when present, enforces actual received-byte limits and promotes only after the writer closes. HTTP failures retain status and Retry-After for caller policy. The loopback fixture exercises truncated transfers, wrong size/hash, path rejection, a chunked size overrun, throttling, successful replacement and last-good preservation. Node 22.16.0: four test groups pass across the two suites. This is scoped transfer correctness, not authenticated redirect policy, crash-durability or native performance evidence. Consumer-specific routing and authorization remain with each host.
