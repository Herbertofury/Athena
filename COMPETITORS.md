# Competing learning experiences and research workflows

Athena combines learning pathways, original practical exercises and an evidence-led engineering workspace. Comparators are scoped by learner journey, not a claim that one academy replaces every specialist. Preserve [coverage limitations](docs/quality/COVERAGE.md) and the [integration status](docs/integration/STATUS.md).

| Comparator and primary source | Documented role | Proposed Athena comparison |
|---|---|---|
| [Microsoft Learn](https://learn.microsoft.com/en-us/training/) | Interactive modules and learning paths | Compare prerequisite clarity, objective mapping and recovery after a learner gets an exercise wrong. Vendor credentials remain independent. |
| [The Odin Project](https://www.theodinproject.com/) | Project-based full-stack curriculum | Compare one complete learn-build-debug-review journey, not number of lessons. Check whether Athena learners can produce and explain a working artifact. |
| [PortSwigger Web Security Academy](https://portswigger.net/web-security) | Web-security learning and practical labs | Compare explanation-to-practice continuity in authorized labs. Do not claim browser simulations equal real security practice. |
| [Existing Atlas research library](engineering/README.md) | Preserved engineering methods and evidence | Use its existing comparison queues, not duplicate candidate rankings inside every learning route. |

## Review and evidence rules

Review date: **2026-11-12**. This is a comparison agenda, not a benchmark result or proof of superiority. Official-source capability descriptions and our proposed experiments are separate. Pin actual versions and licenses before reuse; record publication date separately from the date checked. Retain failed comparisons and rejected candidates.

During recurring reviews, inspect upstream releases, breaking changes, security notices and relevant issue reports; add a dated change note only for a meaningful change. Reuse the existing catalogs instead of creating another disconnected list. A missing observation is **unknown**, not unsupported. No new feature is silently authorized merely by appearing here.

For each proposed adoption, record baseline revision, candidate revision, identical workload, required outputs, correctness/security/compatibility checks, latency distribution, memory and reproducible raw evidence. Never make a target-project superiority claim from a synthetic microbenchmark. Keep private assets and traces out of public evidence.
